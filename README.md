# Тоннаж

Веб-приложение для тренировок в зале на набор массы. Ставится на экран iPhone,
работает в зале без связи, дневник хранится вне браузера.

Главное отличие от таблицы в заметках: **программу ведёт движок**. Он сам решает,
что ты делаешь сегодня, с каким весом и почему, и меняет схему по мере прогресса.

**Установка:** [SETUP-FREE.md](SETUP-FREE.md) — бесплатно, без хостинга и домена,
около 20 минут. Либо [DEPLOY.md](DEPLOY.md) — на свой сервер, если нужен полный
контроль.

## Как это работает

### Программа

Мезоцикл — **4 недели по 3 тренировки**:

| Неделя | Что происходит |
|---|---|
| 1 · Накопление | Базовый объём, в запасе 3 повтора |
| 2 · Рост объёма | +1 подход на базовых движениях, вес тот же |
| 3 · Пик | Диапазон повторов сдвигается вниз, вес выше |
| 4 · Разгрузка | 60% веса, половина подходов |

Программа двигается **по отмеченным тренировкам, а не по календарю**. Пропустил
неделю — блок продолжится с того же места, ничего не сломается.

Блоки чередуют акцент: нечётные — силовые (6–8 повторов в базе), чётные —
гипертрофия (8–10). Смена диапазона сама по себе даёт разнообразие и новый стимул.

### Разнообразие без потери прогресса

Три дня — A (присед и жим), B (тяга), C (объём). Каждый день собран из **слотов**:
слот говорит, какое нужно *движение*, а не какое упражнение.

- **Базовые движения держатся два блока подряд.** Новичку нужна повторяемость:
  присед растёт именно оттого, что ты приседаешь каждую неделю, а не пробуешь
  новое упражнение.
- **Подсобка меняется каждый блок.** Вот откуда берётся разнообразие.
- **Сложные движения открываются со второго блока**, когда базовая техника уже есть.

За восемь месяцев в ротацию выходят все 44 упражнения базы. Проверяется командой
`npm run sim`.

### Прогрессия

Двойная прогрессия с автокоррекцией по твоей отметке после тренировки
(«легко / нормально / тяжело / не добил»):

| Что было | Что сделает движок |
|---|---|
| Все подходы на верхней границе + «легко» | +2 шага веса |
| Все подходы на верхней границе | +1 шаг (2,5 кг верх / 5 кг низ) |
| Верхняя граница, но «тяжело» | Держит вес ещё тренировку |
| «Не добил» | Держит вес |
| Дважды не добрал нижнюю границу | −10%, проходим участок заново |

Отдельно учитываются два случая, на которых ломаются самодельные программы:

- **Разгрузочная неделя не задаёт рабочий вес.** Иначе 60% превращаются в новую
  точку отсчёта, и веса ползут вниз с каждым блоком.
- **Смена диапазона между блоками корректирует вес** (~3% на повтор): с весом
  на 6 повторов десять не сделать.

## Структура

```
Тренировки/
├── web/                     приложение (PWA, чистые ES-модули, без сборки)
│   ├── index.html
│   ├── app.js               экраны и взаимодействие
│   ├── engine.js            движок программы — вся логика тренера здесь
│   ├── exercises.js         44 упражнения: техника, ошибки, схемы движения
│   ├── store.js             состояние, офлайн-очередь, синхронизация
│   ├── doc.js               формат дневника и слияние версий
│   ├── adapters/            хранилища, все с одинаковым интерфейсом
│   │   ├── github.js        приватный репозиторий, история коммитами
│   │   ├── telegram.js      бот и закреплённое сообщение
│   │   ├── server.js        свой сервер
│   │   └── local.js         только браузер
│   ├── figure.js            анимированные схемы движения (SVG из углов)
│   ├── charts.js            графики
│   ├── sw.js                service worker — работа без связи
│   └── manifest.webmanifest
├── server/                  Node 22+, ноль npm-зависимостей — нужен только
│   │                        для варианта «свой сервер»
│   ├── src/index.js         HTTP, статика, API
│   ├── src/db.js            SQLite (node:sqlite) + миграции
│   ├── src/auth.js          пароль (scrypt) и подписанные токены
│   ├── src/sim.js           симуляция программы для проверки движка
│   ├── src/test-merge.js    тесты слияния версий дневника
│   ├── src/make-icons.js    генератор иконок
│   └── deploy/              systemd и nginx
├── .github/workflows/       автопубликация на GitHub Pages
├── SETUP-FREE.md            бесплатная установка
└── DEPLOY.md                установка на свой сервер
```

Сборки нет: браузер грузит ES-модули напрямую. Меньше движущихся частей —
меньше того, что сломается через год само по себе. Все пути относительные,
поэтому приложение одинаково работает и в корне домена, и в подкаталоге
вида `логин.github.io/tonnage/`.

## Запуск локально

Нужен **Node 22.5 или новее** (используется встроенный `node:sqlite`).

```bash
cd server
cp .env.example .env          # впиши пароль
node src/make-icons.js        # иконки, один раз
npm start
```

Открой `http://127.0.0.1:8080`.

Полезные команды:

```bash
npm run dev                   # с автоперезапуском
npm test                      # 17 тестов слияния версий дневника
npm run sim -- 84             # прогнать программу на 84 тренировки вперёд
npm run hash -- твойпароль    # хеш пароля для .env
npm run icons                 # перегенерировать иконки
```

`npm run sim` — главный инструмент при правках движка: печатает, как меняются
веса, схемы подходов и какие упражнения выходят в ротацию за полгода-год.
Проверять программу в зале через восемь месяцев поздно.

**Дымовой тест интерфейса** проходит весь путь пользователя (выбор хранилища →
подключение → план → запись подходов → таймер → оценка → итог → все экраны) и
проверяет 41 условие. Ловит то, чего не видят юнит-тесты: белый экран из-за
ошибки в модуле, кнопку, которая ничего не делает. Требует jsdom, поэтому он
ставится отдельно и в зависимости проекта не входит:

```bash
npm i --no-save jsdom
npm start &                   # тесту нужен живой сервер
npm run smoke
```

jsdom не исполняет `<script type="module">`, поэтому тест не «открывает»
страницу, а поднимает DOM как окружение и импортирует модули приложения
напрямую — см. комментарий в начале `test/smoke.mjs`.

## Данные и хранилища

Весь дневник — один JSON-документ: тренировки, вес тела, настройки. Год занятий
это примерно 80 КБ, поэтому дробить его на записи и городить инкрементальную
синхронизацию незачем — проще целиком прочитать и целиком записать.

Хранилище сменное. Все адаптеры выглядят одинаково, поэтому переезд — это выбор
в настройках, а не переписывание приложения:

| Хранилище | Чем хорошо | Чем платишь |
|---|---|---|
| **GitHub** | Каждое сохранение — коммит, вся история под рукой | Токен надо ввести один раз на телефоне |
| **Telegram** | Не блокируется, настройка за 3 минуты | Токен бота лежит в памяти браузера |
| **Свой сервер** | Полный контроль | VPS, 200–400 ₽ в месяц |
| **Только браузер** | Ничего не настраивать | Safari однажды почистит данные |

Все три сетевых варианта проверены на CORS: браузер может и читать, и писать
без промежуточного сервера. **Яндекс.Диск не подошёл** — его API отдаёт CORS
на чтение, но хосты загрузки и WebDAV не отдают вовсе, то есть записать из
браузера нельзя.

Приложение всегда пишет сначала в локальную копию и только потом отправляет
в хранилище. В зале часто нет связи, и подход, записанный в подвале, не должен
пропасть. Не ушедшие записи лежат в очереди и отправятся сами.

Конфликты разрешаются по последней правке **на уровне отдельной записи**, а не
всего файла. Это важно: если телефон записал тренировку офлайн, а с компьютера
в это время поправили вес тела, при слиянии должно уцелеть и то, и другое.
Проверяется командой `npm test`.

**Резервная копия:** «Ещё → Скачать копию» отдаёт весь дневник одним JSON-файлом.
При восстановлении записи сливаются, а не затирают друг друга.

## Почему такой стек

В прошлом проекте (Delivery_SANY) вскрылись две вещи, которые ломают рабочее
приложение молча и не в момент разработки:

1. **Supabase на бесплатном тарифе ставит проект на паузу после 7 дней без
   запросов.** Приложение просто перестаёт работать.
2. **Прямые запросы к `*.supabase.co` из России блокируются** — там пришлось
   городить прокси через свой домен.

Поэтому здесь нет облачной базы, которая может уснуть, и нет npm-зависимостей
ни на клиенте, ни на сервере. Данные лежат либо в обычном git-репозитории, либо
в Telegram, либо в одном файле SQLite на своей машине. Засыпать нечему,
обновлять нечего.

## Ограничения, о которых честно

- **Это PWA, а не нативное приложение.** Собрать `.ipa` для iPhone нельзя без
  аккаунта Apple Developer (99 $/год) и Mac для подписи. PWA даёт иконку на
  экране, полный экран без адресной строки и работу офлайн; внутри — движок Safari.
- **В бесплатном варианте ты зависишь от чужих правил.** GitHub и Telegram
  могут их однажды поменять. Поэтому в приложении есть выгрузка дневника файлом,
  а серверный вариант остаётся запасным путём и переезжает одним переключателем.
- **Токен хранилища лежит в памяти браузера.** Для GitHub он ограничен одним
  приватным репозиторием, для Telegram — одним ботом. Компрометация означает
  доступ к дневнику тренировок, не более того, но знать об этом стоит.
- **Ролики по технике открываются поиском на YouTube** по названию упражнения.
  Хостить видео приложение не может, а зашивать конкретные ссылки рискованно —
  они мрут.
- **Расчёт калорий — оценка** по формуле Миффлина–Сан Жеора, а не медицинская
  рекомендация.
- **Схемы движения — стилизованные**, они показывают траекторию и фазы, а не
  анатомию. Текст с подсказками и разбором ошибок несёт основную нагрузку.
